# 志愿者面试排班

一个蓝色、简洁的浏览器排班工具：导入两份问卷，编辑识别后的名单，自动生成候选人面试、面试官和场务安排。

[在线使用](https://turtleneck1109-design.github.io/volunteer-interview-planner/)

## 功能

- 导入 `.xlsx` 问卷，自动识别表头、日期和时间区间。
- 两个上传框内可分别下载候选人、工作人员 Excel 模板，内附填写说明，支持离线下载。
- 候选人及工作人员名单支持搜索、分页、新增、编辑、单条/批量删除和撤销。
- 编辑姓名、编号、面试方式、部门及各角色可用时间后，立即重新排班。
- 在「面试安排」逐人调整时段、面试官和起止时间，可查看空档、撤销或恢复自动安排。
- 手动调整自动保存，热力图、工作量和 Excel 三张工作表同步更新。
- 默认每 20 分钟一个到场批次，间隔可设为 1—240 分钟；支持默认教室和按日期指定教室。
- 可切换批次候场或具体安排，单独导出「面试时间、候场教室、姓名、学工号」四列查询表。
- 5 分钟是参考，优先最大化可安排人数；必要时自动缩短，时间精确到秒。
- 一位候选人对应一位面试官，不超出可用时段，不重叠面试，不同时兼任场务。
- 热力图仅显示人均可用时间，默认每 20 分钟一场；点击格子查看该场名单，支持下载 SVG 图表。
- 导出标准 Excel，包含「候选人面试安排」「面试官排班」「场务排班」三张工作表。
- 浏览器本机保存名单与设置；下载当前网页可生成独立离线备份。

## 使用

1. 打开网页，在「名单管理」下载两份模板并填写，或直接选择已有的候选人问卷和工作人员问卷。
2. 点击「识别名单」，在表格中检查、修改人员信息和可用时间。
3. 在「排班总览」调整参考时长、场务人数、间隔及启用场次。
4. 在「面试安排」点击每行的「调整」，修改时段、面试官及起止时间；需要时可使用首个空档。
5. 在「设置间隔与教室」填写批次间隔和候场教室，点击「应用设置」。候选人按批次开始时间到场候场。
6. 「导出查询表」生成四列的候选人通知表；顶部「导出 Excel」保留三张完整排班表，并附到场通知时间和教室。

也可从空名单手动录入，或点击「试用示例」。示例中的人物和编号均为虚构。

到场批次以各可用时段的开始时间为起点，将当前已安排人员按面试开始时间归入相应批次；最后一批不足设定间隔时，截止到扣除预留后的时段末尾。批次是到场候场通知，批次区间不代表每个人的面试时长，也不承诺批次结束前全部结束。具体面试仍按原方案执行，平均面试时长与覆盖人数保持原口径。手动调整后批次自动更新；修改批次间隔不会移动具体面试时间。

热力图按到场批次划分，间隔与批次设置同步。每格 = 本场面试官可用总分钟（扣除必要间隔）÷ 本场候选人数，包含尚未使用的时间；候选人按面试开始时间计入一场。空场显示「—」，末场按扣除预留后的实际长度计算。跨批次的必要间隔按与各场重叠的分钟分摊。

教室按「当日教室 → 默认教室 → 待定」取值；线上候选人显示「线上等候」。按日期教室留空时使用默认值。查询表始终导出全部候选人，待安排者也会保留并标记「待安排」。仅需部分结果时可使用「导出筛选 CSV」。

手动调整只改变所选候选人，其他候选人的安排保持不变。保存时检查可用时段、面试官角色、场务人数、间隔、末尾预留和时间重叠；不符合时保留原方案并显示原因。起止时间可填写 `18:00` 或 `18:00:30`，单次时长范围为 1 秒至当前参考时长。

修改名单、排班参数或人员分工时，保留有效的手动调整；若与新方案冲突，此次修改不会保存，可先调整对应人员或点击「恢复自动排班」。导入两份新问卷或载入示例会重新排班。撤销可恢复上一步，刷新后撤销记录清空；手动安排本身会保留，保存当前网页也会包含这些调整。

## 导入格式

读取工作簿首张工作表。候选人表包含：学号（或候选人编号）、姓名、面试时间、线上面试（是/否）。工作人员表包含：姓名、部门（可选）、面试官时间、场务时间。

模板第一张表为空白填写页，从第 2 行开始，一人一行；第二张「填写说明」中的虚构示例不会导入。学号列为文本格式，可保留前导零。候选人的「线上面试」填写「是」或「否」，工作人员不担任的角色时段留空。可继续向下填写，不受预设行数限制。

时间例子：`2027-01-16 09:00-11:00`、`1月16日 14:00-16:00`，多个区间用顿号、逗号、分号或换行隔开。未注明年份时，使用界面上设置的年份。不支持跨午夜；结束时刻可以是 `24:00`。重叠区间会拆分为不重叠场次，单次面试不跨边界。

## 本地运行

仅需 Python 3 构建，不依赖第三方包或外部 CDN。

```sh
python3 build.py --public
python3 -m http.server 8000 --directory dist
```

打开 `http://localhost:8000`。也可直接用浏览器打开 `dist/index.html`。Excel 导入需支持 `DecompressionStream('deflate-raw')` 的现代浏览器。

测试需要 Node.js：

```sh
node test.cjs
```

如果需要将自己的问卷打包进离线文件：

```sh
python3 build.py "候选人.xlsx" "工作人员.xlsx" "private-planner.html" 2027
```

该文件包含你的名单，仅用于本地备份，请勿提交到公开仓库。

## 排班方式

先安排场务，尽量保留面试官，再用最大流求最大覆盖人数。参考时长不足以覆盖时，按秒搜索可保持最大覆盖的最长公共时长，再为较空的场次恢复时长，最多达到参考值。每场各面试官人数差不超过 1，并兼顾累计面试数量。

间隔、末尾预留、场务最低人数、手动停用场次和问卷可用时间均为硬约束。时长最小为 1 秒；确实不可安排的人员会保留在待安排列表中。线上面试默认所有面试官均可参与，会议链接和教室需自行设置。

## 数据与部署

公开构建默认不含名单，仓库只带虚构示例。导入、编辑、计算和导出在浏览器内完成，应用没有上传名单的接口。浏览器本机保存仅针对当前站点，不支持多人同步编辑；清空名单可移除当前草稿，关闭页面会清空撤销记录。

当前公开网站由 GitHub Pages 从 `main` 分支的 `docs/` 目录发布。修改代码后，运行 `python3 build.py --public docs/index.html` 并提交即可更新网站。将 `dist/index.html` 发布到其他静态网站服务也可使用。`build.py --public` 始终构建空名单入口。仓库不包含原始问卷、真实人员安排或历史私人数据。

## 文件

- `scheduler.js`：时间识别、排班和约束校验。
- `records.js`：名单增删改、稳定人员身份及设置保留。
- `adjustments.js`：手动排班、空档、冲突检查与统计同步。
- `batches.js`：到场批次、候场教室与查询表数据。
- `app.js` / `template.html`：交互和样式。
- `excel-export.js` / `excel-template.js` / `excel-query-template.js`：离线排班与查询表 Excel 导出。
- `templates/` / `import-templates.js`：空白导入模板及离线下载数据。
- `build.py`：构建独立 HTML。
- `demo.json` / `test.cjs` / `test-adjustments.cjs` / `test-batches.cjs`：虚构示例与功能测试。
